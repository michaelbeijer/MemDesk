One-time Google setup

Use the Google Cloud project you already set up for your dashboard. Its Gmail API is enabled and its consent screen is Internal, so all you need is one new OAuth client.

  1. In APIs & Services → Credentials, choose Create credentials → OAuth client ID, application type Web application.
  2. Under Authorised redirect URIs, add the redirect URI above, exactly as shown.
  3. Create it, then paste the Client ID below. No client secret is needed.
  4. Optional: under Google Auth Platform → Data access, add the …/auth/gmail.modify scope, so the consent screen lists what this asks for.
Starting from a fresh Cloud project instead?
  1. Create a project at console.cloud.google.com.
  2. APIs & Services → Library → Gmail API → Enable.
  3. Set up the OAuth consent screen with user type Internal (available on Google Workspace accounts; it avoids Google's review and the seven-day token limit of test mode).
  4. Then follow the four steps above.

OAuth client

The test opens Google's sign-in so you can pick an account, then reads that mailbox's address back from Gmail. It sends nothing and changes nothing.

In Gmail

Board buttons

Bottom right sits over Gmail's compose windows. With the buttons hidden, the board is still a click on the toolbar icon or a keyboard shortcut away.

Keyboard shortcut: Alt+Shift+K

Shortcuts are managed by Chrome at chrome://extensions/shortcuts.

Privacy

There is no server. The access token lives only in this browser's session storage and is gone when Chrome closes. Card order is kept in this browser; your column layout and your own card titles, notes and colours sync through your Chrome profile and are never written to your mail. The extension never sends or deletes mail.
